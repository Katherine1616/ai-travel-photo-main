# FORME AI 虚拟试衣：AI 工具使用说明

## 1. 使用的工具

- **Codex：**分析原始代码、检索参考项目、梳理产品状态机、实现 Vite 网页 Demo、响应式适配、自动化测试、Git 提交与 GitHub 推送。
- **OpenAI ImageGen：**辅助制作预生成试穿素材；素材用于保证 Demo 稳定，不承担产品判断或运行时推理。
- **浏览器自动化：**逐步回归“选款—创建形象—生成—换款/换色—扫码承接”，检查窄屏和 1440 × 900 大屏布局、素材路径、取消生成及异常状态。
- **Git / GitHub：**按功能拆分提交，保留完整迭代记录并公开源代码。

## 2. 关键提示词（整理优化后）

以下内容不是对话原文，而是根据实际迭代过程整理出的可复用 Prompt。

**Prompt 1：先定义核心矛盾与产品分工**

> 你是一名负责门店数字化转化的 AI 产品经理。目标用户已经对某件商品产生兴趣，但可能因隐私顾虑、试衣成本或决策不确定而离开。请围绕“降低从看到商品到愿意试穿或购买的门槛”设计方案。区分门店大屏与手机的职责：大屏应匿名、低投入、适合公共场合；手机承接精确参数、库存、收藏和交易。输出核心用户、主路径、关键转化指标，并指出哪些信息不应在公共大屏展示。

这条 Prompt 决定了“不使用真人照片、匿名形象、大屏降门槛、手机做深度承接”的整体方向。

**Prompt 2：在作业约束下确定 MVP 边界**

> 这是一个面试作业原型，不接真实虚拟试衣模型、库存、登录或支付后端。请把能力分为“必须真实可操作”“可以用状态模拟”“本轮不做”三层。原型需要完整展示提交任务、等待、成功、失败、超时、取消和购买承接，但必须显式说明模拟边界。设计前端数据结构，使预生成素材未来可以替换为真实模型返回结果，而不需要重做用户流程。

这条 Prompt 促成了“前端状态机 + 预生成素材”的实现：牺牲实时推理，换取稳定、完整且诚实的演示，同时保留未来接后端的任务生命周期。

**Prompt 3：用行为意图审查操作链路**

> 请逐步审查“浏览商品—创建形象—生成—查看结果—换款—购买”链路，不以页面数量为唯一标准，而以用户是否已经表达明确意图为判断依据。删除没有新增信息的二选一页和确认页；但不能把点击商品卡等同于确认试穿，因为用户可能只是在浏览。已有形象时，商品卡只更新当前商品，必须点击“使用当前形象试穿”才生成。结果页需要提供调整形象、换款和取消生成后的恢复路径，并验证所有异步定时器都能真正停止。

这条 Prompt 推动了两轮关键调整：先压缩冗余页面，再把“试穿确认”放回正确的意图节点，而不是机械追求最少点击数。

## 3. 参考如何影响取舍

参考案例没有被当作功能清单直接搬运，而是用于回答三个问题：真实虚拟试衣的输入与推理成本有多高、门店大屏常见的交互模式是什么、生成任务需要哪些状态。由此形成三项取舍：

1. **复用任务结构，不复用技术栈。**参考案例中的“提交—等待—结果—异常”适合本场景，但小程序框架、摄像头拍摄和实时 AR 不符合网页交付与匿名体验目标，因此重新实现为独立 Web 状态机。
2. **理解真实模型，暂不接入真实模型。**真实方案需要稳定的人像与服装输入、GPU 推理、排队、内容安全和结果存储。作业重点是产品流程，因此本版用预生成素材模拟相同任务生命周期，并在方案中明确边界。
3. **借鉴交互模式，不复制代码和素材。**商品选择、等待反馈和结果承接只作为信息架构参考；品牌、页面结构、文案、状态逻辑、素材映射和手机分工均按本题场景重新设计。

## 4. 本人完成的主要工作

1. **重新定义问题，而不是直接做“AI 换装”。**我把问题从“生成一张试衣图”改写为“降低顾客从看到商品到进一步决策的门槛”，并据此定义北极星指标和试穿启动、生成完成、扫码、门店 30 分钟成交等漏斗指标。这个定义决定了 Demo 必须同时覆盖吸引、等待、结果比较和交易承接，而不能停留在生图页面。
2. **设计两条互补路径。**对尚未建立信任的顾客提供“先看示例效果”，让价值先于参数填写出现；对准备体验的顾客提供三段式快捷表单，并把精确身体参数转移到手机。这样既降低公共场合输入压力，也保留更高精度的升级路径。
3. **通过迭代处理“效率”与“意图确认”的冲突。**初版存在创建方式二选一页和生成前确认页，链路过长；压缩后又出现点击商品卡即生成、把浏览误判为试穿意图的问题。我删除无信息增量的页面，但保留首页“使用当前形象试穿”作为显式确认，使流程更短却不误触发。
4. **建立可解释的画像映射。**将身高范围、整体体型和身体比例组合为九种内部画像；手机端身高、体重和胸腰臀通过 BMI、胸臀差和腰围比例等规则映射到同一画像体系。界面只展示用户能理解的选择和结果，不暴露“离散化”等内部实现术语。
5. **把 Demo 状态设计成未来接口契约。**我没有简单用延时跳页，而是建立生成进度、成功、失败、超时、取消和结果失效状态，并按商品、颜色和画像组织素材路径。未来接入真实模型时，可以将前端计时器替换为任务 ID 与轮询结果，页面结构和异常路径无需重做。
6. **补齐隐私和交易边界。**大屏不启用摄像头、不要求登录或支付；身体参数不进入会员或订单。方案中同时如实标明当前二维码携带的最小结果参数、45 秒固定倒计时与生产方案的差异，避免把 Demo 状态包装成真实能力。
7. **用回归验证产品判断。**我针对完整主链路、九种画像素材、颜色切换、尺码选择、导航跳转和异常状态进行浏览器验证。测试中发现并修复了商品卡误触发生成、取消生成后延迟定时器仍跳转结果页、窄屏预览遮挡快捷表单等问题，而不是只验证页面能打开。
8. **完成可交付工程。**将原小程序思路重构为 Vite 网页应用，完成响应式大屏与手机页面、二维码模拟联动、Vercel 配置、Git 分支与提交记录。素材生成只占辅助部分，最终保留 108 张试穿结果和 9 张基础形象以保证演示稳定。

AI 主要用于加速方案探索、代码实现和素材生产；关键问题定义、方案取舍、流程迭代、隐私边界、文案、验收标准和最终提交内容均由本人决定并审阅。
